# sing-box 内核：版本选择、更新与回滚

sing-box 是 FlowZX 的主核。它的版本、来源和更新都在「设置 → 高级 → 内核管理」卡中管理。Xray sidecar 有自己的卡片，见 [XRAY.md](XRAY.md#切换-xray-版本)。

卡片顶部显示当前版本，旁边有两类徽章：

- **来源**：官方 / 第三方（fork）/ 未知，根据 `sing-box version` 的版本串自动识别。
- **通道**：「随包」表示当前就是安装包自带的版本；「预发布」表示当前是你装的 alpha / beta / rc 版本。

## 选择 sing-box 版本

「选择版本」从 [SagerNet/sing-box](https://github.com/SagerNet/sing-box/releases) 的 GitHub Releases 列出版本，按版本号从新到旧排序。

**列表规则**

- 只列出带本平台官方构建的版本，草稿不会出现。
- 选项后会标出：预发布、当前、随包、待生效（自动更新已下载）、跨版本带、曾失败。
- 列表由主进程缓存 10 分钟，「刷新列表」会强制重新获取。未登录的 GitHub API 每个 IP 每小时只能请求 60 次，被限流时会提示稍后再试。

**按钮**

按钮随所选版本变化：

| 按钮         | 何时出现                               | 做什么                                                             |
| ------------ | -------------------------------------- | ------------------------------------------------------------------ |
| 安装         | 所选版本既不是当前版本，也不是随包版本 | 下载、校验、预检后切换                                             |
| 恢复随包     | 选中了随包版本，但当前不是它           | 走「重置内核到出厂」的流程。使用本地文件，不下载，并会删除现有备份 |
| 已是当前版本 | 所选版本就是当前版本                   | 无（按钮不可点）                                                   |

**最低版本 = 随包版本**

最低可选版本就是 `src/shared/core-manifest.json` 中的 `bundledCoreVersion`（FlowZX 4.6.0 为 1.14.0-rc.1）。它随安装包变化，不是写死的数字。

更旧的版本不会列出，主进程也会拒绝安装（`BELOW_MINIMUM`）。原因有两个：

- 比随包版本旧的官方内核，会在下次连接或启动时被自动换回随包版本。
- 1.13.x 不认识 FlowZX 生成的 1.14 配置字段，例如 `store_dns` 和路由的 `resolve` 超时。

**预发布**

- 默认只列正式版。打开「包含预发布版本」后，同时列出 alpha / beta / rc：GitHub 标为 pre-release 的版本，或 tag 带这些后缀的版本，都算预发布。
- 当前版本和随包版本始终显示，即使它们本身是预发布。随包的 1.14.0-rc.1 就是这种情况。
- 这个开关只影响列表。「检查更新」和自动更新始终只看正式版。

**跨版本带**

- 跨版本带的版本是指 major.minor 高于随包版本的版本，例如随包为 1.14.x 时的 1.15.0-alpha.\*。
- FlowZX 生成的配置没有针对这些版本验证过，所以安装前需要确认。「限兼容版本带」开关只约束「检查更新」，不约束这里。

**确认框**

需要确认时，确认框会逐条列出原因：

- 预发布；
- 跨版本带；
- 旧于当前版本；
- 曾失败；
- 会替换第三方内核；
- 待生效的自动更新会作废；
- 自动更新稍后会把所选版本升级掉（见下文「固定版本与自动更新」）。「恢复随包」也会提示这一条，但它不能固定版本：想停在随包版本，请先关闭自动更新；
- 代理会重启。

**第三方内核**

- 当前是第三方内核时也可以安装官方版本。确认后，第三方内核会保留为备份，可以用「回滚内核」找回。
- 「恢复随包」和「重置内核到出厂」不保留备份，确认框会专门提示这一点。

**macOS**

在线安装需要支持 install-core 的提权助手（「设置 → 网络」中的提权助手），否则只能改写 App 包内的随包内核，因此会被拒绝（`HELPER_REQUIRED`）。

**Windows（TUN 模式的提权服务）**

提权服务只运行安装服务时锁定的那个 sing-box。第一次在线安装（或「检查更新 → 更新」）会把当前内核换到用户数据目录下的 `core_update`，此后服务锁定的路径就与当前内核不一致：

- 「设置 → 网络」的提权服务卡片显示「内核已更换，需修复」；下次以 TUN 连接时会提示修复。修复会重装服务并锁定当前内核，需要一次 UAC 授权。
- 修复之前，TUN 模式改用 UAC 启动当前内核，不会再经服务运行旧内核。

### 完整性校验

渲染端只把 tag 交给主进程。release、资产和摘要都由主进程按 tag 重新向 GitHub API 查询。

1. **资产**：按精确文件名挑选，只认以下四个：

   | 平台             | 资产文件名                            |
   | ---------------- | ------------------------------------- |
   | Linux x64        | `sing-box-<版本>-linux-amd64.tar.gz`  |
   | Windows x64      | `sing-box-<版本>-windows-amd64.zip`   |
   | macOS Intel      | `sing-box-<版本>-darwin-amd64.tar.gz` |
   | macOS Apple 芯片 | `sing-box-<版本>-darwin-arm64.tar.gz` |

   与打包所用的 `scripts/fetch-core.mjs` 相同。`-glibc`、`-musl`、`-legacy-*` 等变体永远不会被选中。下载地址必须正好是 `https://github.com/SagerNet/sing-box/releases/download/<tag>/<资产名>`。

2. **摘要**：SagerNet 不发布 `.dgst` 或 checksums 文件，**唯一的摘要来源是 GitHub API 返回的资产 `digest`（SHA-256）**。拿不到摘要就拒装（`NO_HASH`）。
   - 下载出错时会回落到 GitHub 镜像（你设置的 ghProxy 前缀，未设置时用内置的 gh-proxy）。镜像给的字节同样必须与这份摘要一致，解压前还会对落盘文件再校验一次。
   - 这份校验能证明「文件与 GitHub 上该 release 的资产一致」，但并不是 SagerNet 的签名。信任锚是经 TLS 直连的 api.github.com。

3. **预检**：
   - 解出的 `sing-box version` 必须恰好是所选版本，且是官方构建形态（`VERSION_MISMATCH` / `NOT_OFFICIAL`）。
   - 新内核在本机根本无法执行（架构不符、文件损坏，或临时目录禁止执行程序）时不切换（`EXEC_FAILED`）。这时配置还没检查过，不会记为「曾失败」。
   - 再用新内核执行 `sing-box check`，检查当前配置。不通过就不切换，该版本会被记为「曾失败」，没有「仍然安装」选项（`PREFLIGHT_FAILED`）。弹出的提示会附上 sing-box 的 FATAL 行。

### gVisor（1.15.0-alpha.11 起）

从 1.15.0-alpha.11 起，sing-box 的官方构建不再编入 gVisor（`sing-box version` 的 `Tags:` 行里没有 `with_gvisor`）。

- **影响**：如果 TUN 的网络栈是 gvisor 或 mixed，TUN 模式会在运行时报错（`gVisor is not included in this build`），而 `sing-box check` 照样通过。Auto 在 macOS 和 Windows 上就是 gvisor。
- **安装时拦截**：安装前会读取新内核的 `Tags:` 行。缺少 `with_gvisor`、而当前网络栈解析为 gvisor 或 mixed 时，拒绝安装（`GVISOR_MISSING`）。
- **想用这类版本**：先在「设置 → 网络 → 网络栈」改为 system，再安装。
- **装好之后**：如果再把网络栈改回 gvisor、mixed 或 Auto（macOS / Windows），TUN 将无法启动。

### 生效与自动回滚

**代理未运行时**

- 新内核在下次连接时生效。
- 如果首次启动失败，会自动回滚到原来的内核。

**代理运行中时**

- 先停止代理，换核后再启动，连接会短暂中断。
- 如果起不来：
  - 自动换回原来的内核，并用它重新启动；
  - 提示「已恢复原来的内核」；
  - 该版本记为「曾失败」；
  - 固定恢复到切换前的状态（原来固定着当前版本，就仍然固定）。
- 如果起不来的原因与内核无关（取消了管理员授权或提权助手引导、TUN 地址冲突、端口被其他程序占用）：新内核保留，不回滚，也不记为「曾失败」（`START_BLOCKED`）。排除原因后重新连接即可。
- 重启期间如果你手动停止或连接代理，或退出 FlowZX：以你的操作为准，新内核保留，不回滚，也不再自动启动代理。

**互斥与进度**

- 一次只进行一个内核操作：安装、恢复、「检查更新 → 更新」、自动更新、回滚、手动替换、立即应用、Xray 版本切换互斥，后来的会提示「正在进行中」而不开始。
- 进行中，或代理正在启动 / 停止时，卡内所有操作按钮都不可用。
- 离开设置页再回来，进度仍会显示。

**libcronet（Linux / Windows）**

NaiveProxy 需要的 `libcronet` 始终使用随包版本，压缩包里自带的会被丢弃。Linux 上已实测可与 1.14.0、1.14.3 和 1.15.0-alpha.12 配合使用。

## 固定版本与自动更新

**自动更新（默认关闭）**

- 启动 30 秒后检查一次，此后每 6 小时检查一次；距上次检查不足 24 小时则跳过。
- 目标是全部正式版里版本号最大的那一个，而且只在它与当前版本同属一个 major.minor 时才自动更新。跨版本带的新版只提示。
- 新版下载并预检后先暂存，等代理停止或下次启动时落位；也可以点「立即应用」。

**固定版本**

- 用「选择版本」装了比自动更新目标更旧的版本（同一版本带内）时，如果自动更新开着，确认框会多一个勾选项：「固定此版本（暂停自动更新）」，默认勾选。
- 固定后，卡内显示「已固定 x.y.z，自动更新暂停」。期间自动更新不再检查和下载，已暂存的新版也会作废。手动点「立即应用」或「检查更新 → 更新」不受固定限制。
- 点「取消固定」后，自动更新在下一个 6 小时周期恢复。
- 内核版本被其他途径改变后，固定自动失效：
  - 回滚、手动替换、恢复随包或重置到出厂；
  - 「检查更新 → 更新」、立即应用；
  - App 升级后被换回随包版本。

**兼容版本带的上限**

- 「检查更新」的兼容版本带上限会随成功运行的正式版放宽，但**预发布版不会放宽它**。
- 「恢复随包」或「重置内核到出厂」会把它恢复到随包版本所在的版本带。

## 回滚与恢复

- **回滚内核**：在线安装和「检查更新 → 更新」都会把原内核保留为备份。卡内「备份版本」一行的「回滚内核」可以换回去，第三方内核也一样。
- **恢复随包 / 重置内核到出厂**：用安装包自带的内核覆盖当前内核。
  - Windows / Linux 上会先按 `core-manifest.json` 中的 SHA-256 校验随包内核。
  - 现有备份会被删除，固定和已暂存的新版也一并清除。
- **App 升级**：如果在线装的官方版本旧于新安装包的随包版本，下次启动或连接时会被换成随包版本。

## 报告问题与诊断报告

「关于 → 报告问题」预填的 sing-box 版本和导出的诊断报告，会在版本号后附上简短标注：随包 / 预发布 / 已固定 / 第三方，例如 `1.15.0-alpha.12（预发布 · 已固定）`。
