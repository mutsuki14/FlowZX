## FlowZX 4.4.2 — Xray JSON 订阅、Trojan REALITY 与 Shadowsocks 的 Xray 开关

订阅链接现在可以直接使用 Xray JSON；Trojan 表单支持 REALITY，Shadowsocks 表单可以改用 Xray 内核；「报告问题」预填的环境信息更完整。

### 新增
- **Xray JSON 订阅**：订阅链接支持单份 Xray 配置、Marzban / 3x-ui 等面板的「v2ray-json」配置数组和裸 outbound 数组；手动导入也支持配置数组与裸 outbound 数组（此前无法导入）。节点以各份配置的 `remarks` 命名，没有 `remarks` 时以 `地址:端口` 命名，仍重名时追加配置序号。链式代理（`dialerProxy` / `proxySettings`）转为前置代理，只在同一份配置内解析。订阅更新时节点 id 与前置代理关系保持不变，内容未变时不重启内核。
- **Trojan + REALITY**：Trojan 表单的「安全」新增 Reality（公钥、Short ID、SpiderX、指纹），默认由 sing-box 运行，填写 ML-DSA-65 验证公钥或打开「使用 Xray 内核」时改由 Xray 运行。此前编辑并保存导入的 Trojan + REALITY 节点，会把它改成 TLS 并丢掉 REALITY 设置。
- **Shadowsocks 的「使用 Xray 内核」开关**（表单「高级」中）：使用 SS 插件、Shadow-TLS 或流加密（如 `aes-*-cfb`、`rc4-md5`）时不可用，因为 Xray 只支持 AEAD 与 2022 加密方法。
- **「报告问题」预填更多信息**：新增 Xray 版本与运行状态、当前选中节点由哪个内核运行及原因（含前置代理是否经过 Xray）、分流策略；接管方式可显示「仅本地代理」。仍不含节点地址、节点名或凭据。issue 模板同步更新，并提醒实时日志需给节点名打码、诊断报告的日志明细仍可能含访问过的其它域名 / IP、订阅服务器域名与本机文件路径。

### 修复
- Xray JSON 手动导入：`direct` / `block`（`freedom` / `blackhole` 的协议别名）不再被当作节点导入；TCP / RAW 带 HTTP 伪装头的出站改为以「自定义 Xray 出站 JSON」原样导入，此前伪装头被静默丢弃，节点无法连接；outbounds 同时含 sing-box（`type`）与 Xray（`protocol`）条目的文件按 sing-box JSON 解析，不再跳过其中的 sing-box 节点。
- REALITY 节点的 uTLS 指纹选「无」时改按 `chrome` 下发。此前 sing-box 会因此无法启动整份配置，Xray 也会拒收。
- WebSocket / HTTPUpgrade 上的 REALITY 节点不能再切到 Xray（Xray 的 REALITY 只支持 RAW / gRPC / XHTTP）；VLESS / Trojan 表单只在这三种传输下显示 ML-DSA-65 与 SpiderX，其它传输上不再提交 ML-DSA-65，避免节点被交给拒收它的 Xray。
- 由 Xray 运行的 Shadowsocks 节点统一以小写下发加密方法名，大写的 2022 方法名不再被 Xray 拒收。
- 「连接」页的「规则」与「源」列过长时以 … 截断，不再从字符中间切开。
- README 截图改为 FlowZX 自身界面（演示数据），可以看到 Xray 角标与 Xray 内核状态。

### 4.4.0 用户请注意
4.4.0 的应用内更新仍会检查上游 FlowZ，请从 [Releases](https://github.com/mutsuki14/FlowZX/releases/tag/v4.4.2) 手动下载并覆盖安装 4.4.2（节点、订阅与规则会保留；便携版请用新 exe 替换原目录中的旧 exe，数据在它旁边的 `data\`）。4.4.1 及以上版本可直接在应用内更新。如果 4.4.0 提示有新版本，请不要安装：那是上游 FlowZ 的安装包，不含 Xray 内核。

## FlowZX 4.4.2 — Xray JSON subscriptions, Trojan REALITY and an Xray switch for Shadowsocks

**Subscription URLs now accept Xray JSON**: a single config, the "v2ray-json" config arrays served by panels such as Marzban / 3x-ui, or a bare outbound array (Manual Import now accepts config arrays and bare outbound arrays too; 4.4.1 couldn't import them). Nodes are named after each config's `remarks`, or `address:port` when there is none, with the config's position appended if names still collide. `dialerProxy` / `proxySettings` chains become detours, resolved within the same config; node ids and detours stay stable across updates, and an unchanged subscription doesn't restart the core. **The Trojan form supports REALITY** (runs on sing-box by default, on Xray when an ML-DSA-65 key is set or **Run on Xray core** is on); editing an imported Trojan + REALITY node no longer turns it into TLS. **The Shadowsocks form has Run on Xray core**, unavailable with SS plugins, Shadow-TLS or stream ciphers, since Xray only supports AEAD and 2022 methods. **Report an issue** now also prefills the Xray version and status, which core runs the selected node and why (including a detour through Xray), and the routing mode; the takeover mode it fills in can now also be Local Only. It still includes no node addresses, names or credentials. The issue template now asks you to mask node names in the live log too and notes that diagnostic report logs may still contain other visited domains / IPs, the subscription server's domain and local file paths.

**Fixes:** Manual Import of Xray JSON no longer imports `direct` / `block` outbounds as nodes, imports TCP / RAW outbounds with HTTP header obfuscation as custom Xray outbound JSON instead of silently dropping the header, and parses files mixing sing-box (`type`) and Xray (`protocol`) outbounds as sing-box JSON. A REALITY fingerprint of "None" is now sent as `chrome` (sing-box previously failed to start the whole config, and Xray rejected it). REALITY over WebSocket / HTTPUpgrade can no longer be switched to Xray, and the VLESS / Trojan forms only show ML-DSA-65 and SpiderX on RAW / gRPC / XHTTP and no longer save ML-DSA-65 on other transports, so such nodes aren't handed to an Xray that rejects them. Shadowsocks methods sent to Xray are lowercased, so upper-case 2022 method names work. Long values in the Rule and Source columns of the Connections page are truncated with an ellipsis. The README screenshots now show the FlowZX UI itself, with demo data.

**Upgrading from 4.4.0:** 4.4.0's in-app updater still checks upstream FlowZ, so download 4.4.2 from the [Releases page](https://github.com/mutsuki14/FlowZX/releases/tag/v4.4.2) and install it over your current version (nodes, subscriptions and rules are kept; for the portable build, replace the old exe in its folder, since its data lives in `data\` next to it). 4.4.1 and later update in-app. If 4.4.0 reports a new version, don't install it — it is an upstream FlowZ build without the Xray core.
