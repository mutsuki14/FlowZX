## FlowZX 4.6.0 — 切换 sing-box 内核版本（含预发布版）

「设置 → 高级 → 内核管理」新增「选择版本」：可以在线安装 SagerNet 官方发布的任意 sing-box 版本（包括 alpha / beta / rc 预发布版），按 GitHub 提供的 SHA-256 校验、用当前配置预检后切换，可固定版本暂停自动更新，随时恢复随包版本。用法与 4.5.0 的 Xray 版本选择一致，详见 [docs/CORE.md](https://github.com/mutsuki14/FlowZX/blob/main/docs/CORE.md)。

### 新增
- **sing-box 版本选择**：
  - 下拉列表只列出有本平台官方构建的版本，并标出预发布 / 当前 / 随包 / 跨版本带 / 曾失败；可打开发行说明。
  - 列表由主进程缓存 10 分钟，「刷新列表」强制刷新。
  - 选中随包版本时按钮变为「恢复随包」。
- **包含预发布版本**开关：
  - 默认只列正式版，打开后同时列出 alpha / beta / rc。
  - 它只影响这个列表；「检查更新」和自动更新始终只看正式版。
- **最低版本 = 随包版本**（本版为 1.14.0-rc.1）：更旧的 sing-box 不认识 FlowZX 生成的配置，而且会在下次连接时被换回随包版本，因此不提供，主进程也会拒绝安装。
- **完整性与兼容性检查**：
  - 下载地址与摘要由主进程按版本号现查 GitHub。只认官方资产的精确文件名，下载地址必须是 SagerNet 官方发布地址。
  - 压缩包须匹配 GitHub API 给出的 SHA-256（SagerNet 不发布 checksums 文件，取不到摘要则拒绝安装）。走镜像下载时同样要匹配，解压前再校验一次。
  - 新内核的 `sing-box version` 须与所选版本一致且为官方构建，再用它 `sing-box check` 当前配置；不通过则不切换，并把该版本记为「曾失败」。
- **gVisor 提醒**：1.15.0-alpha.11 起的官方构建不含 gVisor。当前 TUN 网络栈为 gvisor / mixed 时（macOS、Windows 上 Auto 即 gvisor）拒绝安装这些版本，并提示先在「设置 → 网络 → 网络栈」改为 system。
- **固定版本**：
  - 装了比自动更新目标更旧的版本且自动更新开着时，确认框提供「固定此版本（暂停自动更新）」，默认勾选。
  - 固定期间自动更新不检查、不下载，已暂存的新版作废；卡内显示「已固定」，可随时「取消固定」。
  - 回滚、手动替换、恢复随包、「检查更新 → 更新」等改变内核的操作会自动解除固定。
- **安全切换**：
  - 代理运行中会整体重启一次（安装前提示）。
  - 新内核起不来时自动换回原来的内核并重新连接，该版本记为「曾失败」。
  - 若失败原因与内核无关（如取消管理员授权、TUN 地址冲突、端口被占用），保留新内核、不误判。
  - 第三方（fork）内核被替换前需确认，并会一直保留为备份，可用「回滚内核」找回。
- 「报告问题」与诊断报告会在 sing-box 版本后标注随包 / 预发布 / 已固定 / 第三方。

### 修复与改进
- 所有内核操作（安装、恢复、检查更新、自动更新、回滚、手动替换、立即应用、Xray 版本切换）现在严格互斥，后来的会提示稍后再试；进行中时相关按钮不可用，离开设置页再回来仍显示进度。
- 新内核首次启动失败时如果恰好有另一项内核操作在进行，自动回滚会推迟到那项操作结束后执行，不再丢失。
- 「检查更新」改为按版本号选最新正式版，不再依 GitHub 列表顺序（不同分支交错发布时可能选错）。
- Linux 在线更新改为选择标准构建，不再可能选中 `-glibc` 等变体。
- 在已连接状态下切换「自动更新内核」「限兼容版本带」「包含预发布版本」不再重启代理。
- Windows：内核更新或切换后，TUN 模式的提权服务若仍锁定旧内核，提权服务卡会显示「需修复」，TUN 连接时提示修复（一次 UAC）；修复前改用 UAC 启动当前内核，不再悄悄运行旧内核。
- 下载被篡改时始终报告为完整性校验失败（此前镜像重试也失败时会显示为下载失败）。
- `sing-box check` 的报错去掉了终端颜色码，提示里的 FATAL 行更易读。
- 英文界面「Danger zone」标题不再重复；波斯语界面的面板地址显示顺序正确。

### 4.4.0 用户请注意
4.4.0 的应用内更新仍会检查上游 FlowZ，请从 [Releases](https://github.com/mutsuki14/FlowZX/releases/tag/v4.6.0) 手动下载并覆盖安装 4.6.0（节点、订阅与规则会保留；便携版请用新 exe 替换原目录中的旧 exe，数据在它旁边的 `data\`）。4.4.1 及以上版本可直接在应用内更新。如果 4.4.0 提示有新版本，请不要安装：那是上游 FlowZ 的安装包，不含 Xray 内核。

## FlowZX 4.6.0 — Choose the sing-box core version (including pre-releases)

**Settings → Advanced → Core Management** now has a version picker. You can install any official SagerNet sing-box release in-app, including alpha / beta / rc pre-releases. Each install is verified against the SHA-256 digest GitHub provides and checked against your current config before switching. You can pin a version to pause auto-update and go back to the bundled version at any time. It works like the Xray picker added in 4.5.0; see [docs/CORE.md](https://github.com/mutsuki14/FlowZX/blob/main/docs/CORE.md) (Chinese).

**New:**
- **Version picker:**
  - Lists only releases with an official build for your platform, marked pre-release, current, bundled, newer version band, or previously failed, with a link to the release notes.
  - The list is cached for 10 minutes; **Refresh list** forces a refresh.
  - Selecting the bundled version turns the button into **Restore bundled**.
- **Include pre-releases:**
  - Off by default, so only stable releases are listed. When on, alpha / beta / rc releases are listed too.
  - It only affects this list. **Check for updates** and auto-update always use stable releases.
- **Minimum version = the bundled version** (1.14.0-rc.1 in this release). Older sing-box versions don't understand the config FlowZX generates and would be swapped back to the bundled core on the next connect, so they are not offered and are refused.
- **Integrity and compatibility checks:**
  - The main process resolves the download URL and digest from GitHub by version tag. Only the exact official asset name is accepted, and the URL must be SagerNet's official release URL.
  - The archive must match the SHA-256 from the GitHub API. SagerNet publishes no checksum files, so if no digest is available the install is refused. Mirror downloads must match the same digest, and the file is checked again before extraction.
  - The new core's `sing-box version` must match the chosen release and be an official build. It must then pass `sing-box check` on your current config; if it fails, nothing is switched and the version is marked as failed.
- **gVisor guard:** official builds from 1.15.0-alpha.11 on no longer include gVisor. While your TUN stack is gvisor or mixed (Auto means gvisor on macOS and Windows), those versions are refused with a hint to switch **Settings → Network → Network stack** to system first.
- **Pin a version:**
  - If you install a version older than the auto-update target while auto-update is on, the confirm dialog offers **Pin this version (pause auto-update)**, checked by default.
  - While pinned, auto-update doesn't check or download and any staged update is discarded. The card shows the pin with an **Unpin** button.
  - Operations that change the core (roll back, manual replace, restore bundled, Check for updates → Update and others) clear the pin.
- **Safe switching:**
  - If the proxy is running it restarts once, and you are told before installing.
  - If the new core fails to start, FlowZX switches back to the previous core, reconnects, and marks the version as failed.
  - When the failure has nothing to do with the core (for example a cancelled admin prompt, a TUN address conflict or a busy port), the new core is kept and not blamed.
  - Replacing a third-party (fork) core asks for confirmation, and the fork is kept as a backup you can get back with **Roll back**.
- **Reports:** "Report an issue" and the diagnostic report label the sing-box version as bundled / pre-release / pinned / third-party.

**Fixes and improvements:**
- All core operations (install, restore, check for updates, auto-update, roll back, manual replace, apply now, Xray version switch) are now strictly mutually exclusive; a second one asks you to try again later. Related buttons are disabled while one runs, and progress is still shown after leaving and reopening Settings.
- If a new core fails its first start while another core operation is running, the automatic rollback now waits for that operation to finish instead of being lost.
- **Check for updates** now picks the newest stable release by version number instead of GitHub's list order, which could pick the wrong one when branches are released interleaved.
- On Linux, online updates now pick the standard build and can no longer pick a `-glibc` or other variant.
- Toggling **Auto-update core**, **Limit to compatible version band** or **Include pre-releases** while connected no longer restarts the proxy.
- Windows: after a core update or switch, if the privileged service used for TUN mode still points to the old core, the service card shows **Needs repair** and TUN connect offers to repair it (one UAC prompt). Until then the current core is started with UAC instead of silently running the old one.
- A tampered download is always reported as an integrity failure (previously it showed as a download failure when the mirror retry also failed).
- `sing-box check` errors no longer contain terminal colour codes, so the FATAL line in the message is readable.
- The English "Danger zone" heading is no longer duplicated, and the dashboard address displays correctly in Persian.

**Upgrading from 4.4.0:** 4.4.0's in-app updater still checks upstream FlowZ, so download 4.6.0 from the [Releases page](https://github.com/mutsuki14/FlowZX/releases/tag/v4.6.0) and install it over your current version (nodes, subscriptions and rules are kept; for the portable build, replace the old exe in its folder, since its data lives in `data\` next to it). 4.4.1 and later update in-app. If 4.4.0 reports a new version, don't install it — it is an upstream FlowZ build without the Xray core.
