## FlowZX 4.6.1 — 修复 sing-box「选择版本」列表获取失败

### 修复
- **sing-box 版本列表始终获取失败**（所有平台）：4.6.0 的「设置 → 高级 → 内核管理 → 选择版本」会显示「获取版本列表失败 · 无法连接 GitHub，请检查网络」，但其实与网络无关。
  - 原因：sing-box 每个版本现在有 168 个下载文件，一次请求 100 个版本时 GitHub 返回约 33 MB 数据，超过 FlowZX 对 GitHub 响应 16 MB 的安全上限而被中止。
  - 现在改为分页获取（每次 10 个版本），并在覆盖到早于随包版本的版本后停止，通常只需 3–4 个小请求。
- **Xray 版本列表**同样改为分页获取（每次 20 个版本）。此前单次响应约 13 MB，已接近上限，Xray 再增加一些下载文件就会同样失败。
- **「检查更新」**改为分 3 页获取最近 30 个版本（与之前覆盖范围相同），不再单次下载约 10 MB 的数据。
- 某一页获取失败时，已获取的版本照常显示：强制刷新失败不会让列表变短，1 分钟后自动重试。

## FlowZX 4.6.1 — Fix the sing-box version list failing to load

**Fixes:**
- **The sing-box version list always failed to load** (all platforms): in 4.6.0, **Settings → Advanced → Core Management → Choose version** showed "Failed to load the version list · can't reach GitHub", even though the network was fine.
  - Cause: each sing-box release now has 168 download files, so asking GitHub for 100 releases at once returned about 33 MB, which exceeds FlowZX's 16 MB safety limit for GitHub responses, and the request was aborted.
  - Releases are now fetched in pages of 10, stopping once versions older than the bundled one are reached. This usually takes 3–4 small requests.
- **The Xray version list** is now also fetched in pages (20 releases each). Its single response was about 13 MB, close to the limit, so a few more files per Xray release would have broken it the same way.
- **Check for updates** now fetches the latest 30 releases in 3 pages (same coverage as before) instead of one response of about 10 MB.
- If one page fails, the versions already loaded are still shown: a failed forced refresh no longer shortens the list, and it retries automatically after a minute.
