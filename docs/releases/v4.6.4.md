## FlowZX 4.6.4 — 修复在线安装新内核后 NaiveProxy 让内核崩溃

### 修复
- **在线安装的 sing-box（如 1.14.4）配错了 libcronet，NaiveProxy 节点一开始工作内核就崩溃。** Windows 上表现为 TUN 模式下 naive 节点无法启动、日志里有 `0xc0000005`；Linux 同理。新版内核编译时用的 libcronet 比随包的新，而旧版本安装内核时丢掉了官方压缩包自带的库，启动前还会把随包的旧库拷回去。现在 FlowZX 从内核里读出它需要的 libcronet 版本，与随包一致就用随包库，不一致就用官方压缩包自带的那份。在线安装、自动更新、手动替换、回滚时都会跟着处理。
- 本机没有配套库时不再拿随包库凑数：naive 节点会被跳过（内核不再崩溃），选中 naive 节点时会提示原因。
- macOS 不受影响（cronet 已静态编入内核）。

### 升级后需要做的
- 如果之前用 4.6.3 或更早版本在线安装过内核：打开「设置 → 高级 → 内核管理」，会看到提示，当前版本的按钮变成「重新安装」，点一下即可补齐配套的 libcronet（原来的固定版本会保留）。也可以选择恢复随包内核。

## FlowZX 4.6.4 — Fix NaiveProxy crashing the core after installing a newer core online

**Fixes:**
- **A sing-box core installed online (e.g. 1.14.4) was paired with the wrong libcronet, so NaiveProxy nodes crashed the core as soon as they carried traffic.** On Windows this showed up as naive nodes failing to start in TUN mode with `0xc0000005` in the log; Linux is affected the same way. Newer cores are built against a newer libcronet than the bundled one, but older FlowZX versions discarded the library shipped in the official archive and copied the bundled one back before every start. FlowZX now reads the libcronet version a core needs from the core itself: the bundled library is used when it matches, otherwise the one from the official archive. Online install, auto-update, manual replace and rollback all handle this.
- When no matching library is available, FlowZX no longer falls back to the bundled one: naive nodes are skipped (the core no longer crashes), and selecting a naive node explains why.
- macOS is unaffected (cronet is statically linked into the core).

**After upgrading:**
- If you installed a core online with 4.6.3 or earlier, open **Settings → Advanced → Core Management**. A note is shown and the current version's button changes to **Reinstall**; click it to add the matching libcronet (an existing version pin is kept). You can also restore the bundled core.
